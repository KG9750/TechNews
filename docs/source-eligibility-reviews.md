# Source Eligibility Reviews

Status: Initial review matrix
Last updated: 2026-06-02

This matrix applies `docs/source-eligibility-checklist.md` to every first-version seed source in `docs/source-registry.md`. It does not grant blanket production approval. A source can remain `needs_review` while still being useful as a seed source for metadata-only fixtures and manual spike validation.

Default safe behavior for all sources:

- Store source metadata, generated summaries, source links, and selection rationale only.
- Do not store complete article bodies.
- Do not bypass logins, paywalls, anti-bot controls, robots guidance, or API terms.
- Do not download or display source media unless media reuse has been approved for that source.
- Preserve source name, original title, and source URL in every Candidate Item and Briefing Item.

## Review Notes

- arXiv rows are eligible only for metadata-only API access, not for bulk full-text/PDF/image storage.
- Rust Blog and Kubernetes Blog are eligible only for metadata-first, text-only ingestion with source attribution and no default media/full-text archive.
- TechCrunch and Hugging Face now have recorded terms evidence, but remain `needs_review` because automated generated-summary/feed reuse scope still needs owner or legal confirmation.
- AWS, Google AI Blog, Google Cloud Blog, Microsoft Blog, and Stack Overflow Blog now have recorded terms evidence, but remain `needs_review` because generated-summary/feed reuse or content-license scope is still unclear.
- Public media and company news rows remain `needs_review` until source-specific terms, media reuse, and rate-limit rules are recorded.
- The Manual URL Inbox must attach eligibility state to each submitted URL because the source changes per item.
